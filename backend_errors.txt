ОБНАРУЖЕННЫЕ И ДОКУМЕНТИРОВАННЫЕ БАГИ (ДЕФЕКТЫ ИИ-ГЕНЕРАЦИИ):

Баг №1: Блокировка миграций кастомных приложений (App-level Migration Block)
- Симптомы: Штатная команда 'makemigrations' возвращает 'No changes detected', игнорируя новые модели Django во вложенной директории 'apps/'.
- Локальное решение: Выполнен принудительный накат через явное указание модулей в консоли: 'python manage.py makemigrations authentication absences organization projects'.

Баг №2: Нарушение консистентности истории БД (InconsistentMigrationHistory)
- Симптомы: Команда 'migrate' аварийно завершалась из-за конфликта порядка накатывания системного модуля 'admin' и кастомной модели 'authentication.User'.
- Локальное решение: Файл db.sqlite3 полностью очищен от конфликтующих артефактов ИИ-генерации. Миграции успешно применены к чистой схеме в правильной последовательности.

Баг №3: Полное отсутствие файлов конфигурации панели администратора (Missing Admin Module)
- Симптомы: В левой панели Django Admin отображаются только системные "Группы". Все кастомные бизнес-сущности (Employees, Projects, Absences, Tasks) скрыты от графического интерфейса.
- Причина: Архитектурный пропуск ИИ. В структуре проекта (в приложениях apps/*/) физически отсутствуют файлы admin.py, содержащие декораторы @admin.register.

Баг №4: Организационный рассинхрон состава файлов локальной ветки
- Симптомы: При первоначальном ветвлении локальная копия Koroliov862 отстала от удаленного main по составу критических скриптов (test_math_engine.py и backend/apps/algorithm/engine.py).
- Локальное решение: Файлы принудительно подтянуты с сервера напрямую в рабочую ветку через 'git checkout'.

Баг №5: Критический сбой рендеринга админ-панели Django при использовании Python 3.14 (AttributeError).
Симптомы: При переходе на change_list в админке сервер падает с ошибкой "'super' object has no attribute 'dicts'" в файле django/template/context.py.
Причина: В Python 3.14 встроенные объекты super() стали официально копируемыми (__copy__). Из-за этого вызов super().__copy__() в ядре Django вместо копии контекста шаблона возвращает изолированный объект super, не имеющий атрибута dicts. Текущие версии Django (5.1/6.1) архитектурно не адаптированы под это изменение CPython.

Баг №6: Критическая ошибка валидации полей админки при сборке (SystemCheckError / admin.E108).
- Симптомы: При запуске 'runserver' Django блокировал выполнение из-за 5 ошибок контроля системы: значения list_display ссылались на несуществующие атрибуты.
- Причина: ИИ-генератор настроил админку "вслепую", указав дефолтные имена полей (title, status, name, updated_at), которые в реальных моделях Ромы назывались иначе (name, decision, title, decided_at).
- Локальное решение: Проведен полный аудит моделей в apps/absences, apps/organization, apps/projects. Конфигурация list_display переписана под реальную архитектуру полей БД.
